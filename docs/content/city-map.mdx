<h2 id="installation">Installation and first map</h2>

`atlas-city-chart` is this repository's reusable package. It has not been published to the npm registry yet. Build a local package from the repository first.

```sh
# In the Atlas repository (Node.js 22.12+ on the 22.x line, or 24+)
npm ci
npm run pack:package

# In your React application
npm install /path/to/atlas-city-chart-0.1.0.tgz
```

Start with the same basic component that runs in the playground below. Its package imports and default export are included here. Save the playground's **data.json** beside this component, or replace it with your own records. The default theme does not require Tailwind.

<h2 id="reading">How to read the city</h2>

Each building is one company. Districts represent exact combinations of up to three categories. A company in Commerce and Services appears once, in their shared district. Position expresses category membership rather than geographic coordinates or distance.

District colors identify category combinations. Health status controls risk effects: `healthy`, `warning`, or `critical`. These effects can be disabled without changing the data.

Building height uses a **continuous square-root scale adapted to the dataset**. The smallest metric maps to a one-floor house and the largest to a 14-floor building; intermediate values produce continuous intermediate heights. The scale takes the square root of each value’s normalized position between the dataset minimum and maximum, giving smaller and intermediate companies more visible height when large values dominate. Height is not proportional to the metric: twice the height does not mean twice the value. Equal values always produce equal heights. If every company has the same value (including a single company or all zeros), all buildings use the midpoint height.

The scale is shared across districts and recalculated when the dataset changes. Search and selection preserve the scale. Heights express relative values within this dataset; separately supplied datasets can have different scales.

Select a company or use its tooltip to inspect the exact value. The demo uses 40, 250, 1000, and 3000 to show four distinct heights in each district. These are illustrative monthly-revenue amounts, not calculated health scores.

<h2 id="data">Data format</h2>

Each company occupies one lot in the district matching its exact combination of categories. The metric determines height using the adaptive scale explained above; status controls risk effects. District colors identify category membership.

| Field | Type | Contract |
| --- | --- | --- |
| `id` | `string \| number` | Required and unique in the reusable component. |
| `name` | `string` | Nonempty name shown in search and details. |
| `metric` | `{ label, value }` | Nonempty label and a finite, nonnegative number. |
| `categories` | `{ label, value }[]` | 1–3 categories per company; up to 3 distinct values across the dataset. |
| `status` | `string` | `healthy`, `warning`, or `critical`. |
| `updatedAt` | `string?` | Last update, in ISO 8601 with a time zone. |
| `statusChangedAt` | `string?` | Start of the current status; cannot be later than `updatedAt`. |

Use a consistent label for each category identifier and the same metric label and unit across the dataset. Keep each company's ID stable when replacing records.

<h2 id="updates">Update data and handle an empty portfolio</h2>

Choose **Data updates and empty state** in the playground. **Update metrics** replaces the data array with new records and increases values by 600. The scale is recalculated from the new data; adding the same amount to every value preserves relative heights. **Select first company** connects the map selection to an application-owned summary. Updating the selected company's metric also updates that summary.

**Clear companies** passes an empty array and shows an explicit application-owned message. **Restore companies** restores the original sample records. The example preserves IDs and category membership, so updates change metric values without assigning a new identity to each company.

When health changes, update both timestamps. When only the metric changes, preserve `statusChangedAt`. Set `busy` while your own request is pending, and show request errors and retry actions in your application. The reusable map does not fetch customer records.

[Open the data-update example](?example=updates#playground).

<h2 id="props">Props</h2>

These props belong to `CityMap` from `atlas-city-chart/react`.

| Prop | Default | Behavior |
| --- | --- | --- |
| `data` | Required | Company records. |
| `metricDomain` | Computed from `data` | Optional `[min, max]` height domain shared across filtered or paginated views. |
| `monitorData` | `data` | Optional full portfolio for recent-risk monitoring. |
| `theme` | `"default"` | `"default"`, `"tailwind"`, or `null` for a custom theme. |
| `view` | `"iso"` | `"iso"` or `"top"` perspective. |
| `life` / `effects` | `true` | City animation / risk effects. |
| `autoRotate` | `false` | Slow camera rotation. |
| `showDistrictLabels` | `false` | Category and intersection labels. |
| `weather` | `"none"` | `"none"`, `"rain"`, or `"snow"`. |
| `lightingMode` | `"auto"` | `"auto"`, `"day"`, `"twilight"`, or `"night"`. |
| `showControls` | `true` | Camera and scene controls, including the visibility toggle below fullscreen. |
| `showEnvironmentControls` | `false` | Opt in to weather and lighting selectors. |
| `showSearch` / `showDetails` | `true` | Search and selection details, including update and health timestamps. |
| `showMonitor` | `true` | Local clock, company totals, health counts, and latest high-risk entries. |
| `showCompass` / `showInstructions` | `true` | North compass with isometric reset / navigation hints and company range. |
| `busy` | `false` | Temporary interaction lock during updates. |
| `title` / `ariaLabel` | Browser language | Map title and accessible name. |
| `className` / `children` | — | CSS customization and additional content. |
| `onSelect` | — | Receives the selected original company record or `null`. |

With `life={false}`, weather particles pause and lighting returns to daylight. Environment selectors keep local overrides; **Automatic** resumes following the supplied props. See [all features and the weather integration](?page=features#weather).

The eye button directly below fullscreen hides or restores the map's header, search, perspectives, and scene controls. The local clock, monitoring panel, compass, selected-company details, footer, and camera buttons remain available, and hiding controls preserves the current weather, lighting, and other scene settings. Setting `showControls={false}` removes the camera toolbar and scene controls entirely.

**Environment controls are opt-in:** `showEnvironmentControls` defaults to `false`. Add the boolean prop without a value (equivalent to `showEnvironmentControls={true}`) to show the lighting and weather selectors:

```jsx
<CityMap data={companies} showEnvironmentControls />
```

Remove the prop or set `showEnvironmentControls={false}` to hide the selectors. In the playground, click **Run** to apply the change. The scene still follows the `weather` and `lightingMode` props; to remove rain, set `weather="none"`.

The documentation is in English. The embedded map demonstrates the component's actual localization behavior: its controls follow the browser's language (`pt-BR` or `en-US`, with English as the fallback).

<h2 id="events">Events and controls</h2>

Use `onSelect` to connect the map to a detail panel or form. The **Selection and events** playground example demonstrates this flow. `onViewChange`, `onLifeChange`, `onEffectsChange`, `onAutoRotateChange`, and `onDistrictLabelsChange` let your application control those settings.

```jsx
const [view, setView] = React.useState("iso");
const mapRef = React.useRef(null);

<CityMap
  ref={mapRef}
  data={companies}
  view={view}
  onViewChange={setView}
  onSelect={(company) => console.log(company)}
/>;

// Inside an event handler, after the map is ready:
mapRef.current?.zoom(1.2);
mapRef.current?.select(companies[0], true);
```

The ref also exposes `view`, `deselect`, `cancel`, `capture`, `play`, `scrollIntoView`, and `stats`. For advanced composition, the package exports `CityChart` and `EnvironmentControls`. The main entry point exports `defineCityChart`, `cityMark`, `createCityRenderer`, and `cityFocus`.

<h2 id="themes">Themes and styling</h2>

Pass a class and override CSS tokens for that instance. The component does not accept a `style` prop. The playground uses a map height of 360–560 px on desktop and 400 px on small screens. Examples with monitoring, selected-company details, or many controls grow to fit their content; these heights are not clipping boundaries.

Your application chooses its own size using `--atlas-city-height`. Hide optional monitoring and search UI for compact layouts, as the basic example does. UI theme and scene lighting are independent: choose `lightingMode` explicitly when you need a repeatable daytime scene. Automatic lighting follows the user's local clock.

```css
.my-city {
  --atlas-city-height: 640px;
  --atlas-city-accent: #7c3aed;
  --atlas-city-on-accent: #fff;
  --atlas-city-radius: 12px;
  --atlas-city-font-family: system-ui, sans-serif;
}
```

```jsx
<CityMap data={companies} className="my-city" theme="default" />
```

For Tailwind 4 projects, also import `atlas-city-chart/tailwind.css` in your Tailwind-processed stylesheet and use `theme="tailwind"`. Public classes and the complete list of tokens are documented in the [package guide](https://github.com/raphox/atlas/blob/main/packages/city-chart/README.md).

<h2 id="rendering">Rendering, accessibility, and WebGL errors</h2>

The 3D map requires a browser with WebGL and graphics acceleration. Server rendering produces an accessible shell; it does not render a static city image or an SVG fallback.

If WebGL initialization fails, the map displays an accessible error message and disables unavailable controls. The chart stops reporting itself as loading. Enable WebGL or graphics acceleration, try a supported browser, and then use **Reset example** or reload the page to retry. If an existing graphics context is lost, reload the page to restore it. Your customer data remains owned by your application.

You can test this behavior by opening the documentation with WebGL disabled. This is separate from the editable-code error box, which reports JavaScript or JSX errors, and from the data-validation message for malformed JSON.

Provide an informative `ariaLabel`. Keyboard users can move through companies using the chart host, select records, use `+`/`-` for zoom, press `0` for the overview, and press Escape to clear selection. Reduced-motion preferences reduce animation and disable particles. Unmounting the component releases its WebGL resources, observers, and event listeners.

<h2 id="deployment">Deploying to GitHub Pages</h2>

Documentation has its own build: `@mdx-js/rollup` compiles MDX, and React Live runs the examples. The output is entirely static, with examples executed on the client.

```sh
npm run dev:docs      # http://127.0.0.1:4174
npm run build:docs    # Builds dist/docs
npm run preview:docs # http://127.0.0.1:4174/atlas/
```

The independent **Tests** workflow runs on each push to `main` and appears separately in GitHub Actions. It runs unit tests, both browser-test shards, and the documentation build/browser tests. When all pass on `main`, **Documentation → GitHub Pages** checks out that exact tested commit, builds `dist/docs`, and publishes it. To deploy manually, run **Tests** on `main`; tests on other branches do not deploy. If a prerequisite fails, is cancelled, or is skipped, deployment is skipped and the current site stays published. Set the repository's **Settings → Pages → Source** to **GitHub Actions**. `DOCS_BASE_PATH` sets the base path; the workflow reads it from Pages metadata. Local production builds default to `/atlas/`.

Screens use query parameters and fragment links, so direct links and reloads work on static hosting without rewrite rules. Edit `docs/content/` to maintain the MDX content, and `docs/examples.js` to add examples.
