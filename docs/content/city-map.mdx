<h2 id="installation">Installation</h2>

`atlas-city-chart` is this repository's reusable package. It has not been published to the npm registry yet. Build a local package from the repository first.

```sh
# In the Atlas repository (Node.js 22.12+ on the 22.x line, or 24+)
npm ci
npm run pack:package

# In your React application
npm install /path/to/atlas-city-chart-0.1.0.tgz
```

Import the component and its stylesheet. The default theme does not require Tailwind or the Atlas application's CSS.

```jsx
import { CityMap } from "atlas-city-chart/react";
import "atlas-city-chart/styles.css";

const companies = [{
  id: "aurora",
  name: "Aurora",
  metric: { label: "Monthly revenue", value: 2400.5 },
  categories: [{ label: "Commerce", value: "commerce" }],
  status: "healthy",
}];

export default function Dashboard() {
  return <CityMap data={companies} lightingMode="day" />;
}
```

The playground provides `React`, `CityMap`, and `companies` in scope. Finish an example with `render(<Example />)`. Arbitrary imports are not supported by the editor. In your own application, use the imports above and export your component normally. JavaScript runs in your browser without a remote compilation service.

<h2 id="data">Data format</h2>

Each company occupies one lot in the district matching its exact combination of categories. The metric controls building size; status controls risk effects.

| Field | Type | Contract |
| --- | --- | --- |
| `id` | `string \| number` | Required and unique in the reusable component. |
| `name` | `string` | Nonempty name shown in search and details. |
| `metric` | `{ label, value }` | Nonempty label and a finite, nonnegative number. |
| `categories` | `{ label, value }[]` | 1–3 categories per company; up to 3 distinct values across the dataset. |
| `status` | `string` | `healthy`, `warning`, or `critical`. |
| `updatedAt` | `string?` | Last update, in ISO 8601 with a time zone. |
| `statusChangedAt` | `string?` | Start of the current status; cannot be later than `updatedAt`. |

Use a consistent label for each category identifier. To update the map, pass a **new array** to `data`; an empty array displays a city with no companies. When health changes, update both timestamps. When only the metric changes, preserve `statusChangedAt`.

<h2 id="props">Props</h2>

These props belong to `CityMap` from `atlas-city-chart/react`. Internal application wrappers may have different defaults.

| Prop | Default | Behavior |
| --- | --- | --- |
| `data` | Required | Company records. |
| `theme` | `"default"` | `"default"`, `"tailwind"`, or `null` for a custom theme. |
| `view` | `"iso"` | `"iso"` or `"top"` perspective. |
| `life` / `effects` | `true` | City animation / risk effects. |
| `autoRotate` | `false` | Slow camera rotation. |
| `showDistrictLabels` | `false` | Category and intersection labels. |
| `weather` | `"none"` | `"none"`, `"rain"`, or `"snow"`. |
| `lightingMode` | `"auto"` | `"auto"`, `"day"`, `"twilight"`, or `"night"`. |
| `showControls` | `true` | Camera and scene controls. |
| `showEnvironmentControls` | `false` | Opt in to weather and lighting selectors. |
| `showSearch` / `showDetails` | `true` | Search and selection details. |
| `busy` | `false` | Temporary interaction lock during updates. |
| `title` / `ariaLabel` | Browser language | Map title and accessible name. |
| `className` / `children` | — | CSS customization and additional content. |
| `onSelect` | — | Receives the selected original company record or `null`. |

With `life={false}`, weather particles pause and lighting returns to daylight. Environment selectors keep local overrides; **Automatic** resumes following the supplied props. See [all features and the weather integration](?page=features#weather).

**Environment controls are opt-in:** `showEnvironmentControls` defaults to `false`. Add the boolean prop without a value (equivalent to `showEnvironmentControls={true}`) to show the lighting and weather selectors:

```jsx
<CityMap data={companies} showEnvironmentControls />
```

Remove the prop or set `showEnvironmentControls={false}` to hide the selectors. In the playground, click **Run** to apply the change. The scene still follows the `weather` and `lightingMode` props; to remove rain, set `weather="none"`.

The documentation is in English. The embedded map demonstrates the component's actual localization behavior: its controls follow the browser's language (`pt-BR` or `en-US`, with English as the fallback).

<h2 id="events">Events and controls</h2>

Use `onSelect` to connect the map to a detail panel or form. The third playground example demonstrates this flow. `onViewChange`, `onLifeChange`, `onEffectsChange`, `onAutoRotateChange`, and `onDistrictLabelsChange` let your application control those settings.

```jsx
const [view, setView] = React.useState("iso");
const mapRef = React.useRef(null);

<CityMap
  ref={mapRef}
  data={companies}
  view={view}
  onViewChange={setView}
  onSelect={(company) => console.log(company)}
/>;

// Inside an event handler, after the map is ready:
mapRef.current?.zoom(1.2);
mapRef.current?.select(companies[0], true);
```

The ref also exposes `view`, `deselect`, `cancel`, `capture`, `play`, `scrollIntoView`, and `stats`. For advanced composition, the package exports `CityChart` and `EnvironmentControls`. The main entry point exports `defineCityChart`, `cityMark`, `createCityRenderer`, and `cityFocus`.

<h2 id="themes">Themes and styling</h2>

Pass a class and override CSS tokens for that instance. The component does not accept a `style` prop.

```css
.my-city {
  --atlas-city-height: 640px;
  --atlas-city-accent: #7c3aed;
  --atlas-city-on-accent: #fff;
  --atlas-city-radius: 12px;
  --atlas-city-font-family: system-ui, sans-serif;
}
```

```jsx
<CityMap data={companies} className="my-city" theme="default" />
```

For Tailwind 4 projects, also import `atlas-city-chart/tailwind.css` in your Tailwind-processed stylesheet and use `theme="tailwind"`. Public classes and the complete list of tokens are documented in the [package guide](https://github.com/raphox/atlas/blob/main/packages/city-chart/README.md).

<h2 id="deployment">Deploying to GitHub Pages</h2>

Documentation has its own build: `@mdx-js/rollup` compiles MDX, and React Live runs the examples. The output is entirely static, with examples executed on the client.

```sh
npm run dev:docs      # http://127.0.0.1:4174
npm run build:docs    # Builds dist/docs
npm run preview:docs # http://127.0.0.1:4174/atlas/
```

The **Documentation → GitHub Pages** workflow publishes `dist/docs` on each push to `main`, after testing the documentation. Set the repository's **Settings → Pages → Source** to **GitHub Actions**. `DOCS_BASE_PATH` sets the base path; the workflow reads it from Pages metadata. Local production builds default to `/atlas/`.

Screens use query parameters and fragment links, so direct links and reloads work on static hosting without rewrite rules. Edit `docs/content/` to maintain the MDX content, and `docs/examples.js` to add examples.
