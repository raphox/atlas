<h2 id="visualization">Visualization and organization</h2>

Atlas transforms records in the browser using Three.js and a TanStack Charts extension. Your backend sends company data; it does not need to calculate positions or geometry.

| Feature | How it works |
| --- | --- |
| Districts and intersections | Up to three distinct categories form up to seven combinations. Each company appears exactly once. |
| Buildings sized by metric | `metric.value` sets height on a continuous square-root scale adapted to the dataset minimum and maximum, with up to 14 floors; exact values and labels appear in details and tooltips. |
| Visual status | `healthy`, `warning`, and `critical` identify health states. `configuring`, `disabled`, and `cancelled` show scaffolding, opaque dark graphite buildings, and ruins. Risk effects can be disabled independently. |
| City life | Cars, pedestrians, traffic lights, and vegetation complete the scene. |
| Rendering | Instanced geometry is reused for buildings, windows, vegetation, traffic, and particles. |

<h2 id="interaction">Navigation and interaction</h2>

Drag with the left mouse button to rotate horizontally, use the wheel or a pinch gesture to zoom, and use the right mouse button or two fingers to pan. Switch between isometric and top views. Press `0` to restore the overview.

Search finds companies by name. Selecting a building opens its details and emits `onSelect`. Fullscreen requests a Screen Wake Lock, when available, to keep the display awake. Exiting fullscreen, hiding the tab, or unmounting releases the lock. Optional automatic rotation pauses during interactions.

Map controls follow the browser's language: `pt-BR` or `en-US`, with English for other locales. Supplied names and labels are preserved. Reduced-motion preferences disable particles and reduce animations. The 3D scene requires WebGL. Initialization failures display an accessible error message; there is no static city fallback. See [rendering and errors](./#rendering).

<h2 id="weather">Weather API integration</h2>

[Open the extension guide](?page=extending#extension-weather) for a working, opt-in Open-Meteo connection with location, caching, and lifecycle cleanup.

The reusable `CityMap` receives a `weather` prop and does not query weather services or request geolocation. The playground's selectors simulate the environment locally.

Connect a provider in your own application and convert its response to `"none"`, `"rain"`, or `"snow"`:

```jsx
<CityMap
  data={companies}
  weather={weatherState.type}
  lightingMode="auto"
/>
```

`weatherState` belongs to your application's integration. Your application manages requests, permissions, caching, refreshes, and failures. Pass `"none"` when weather is unavailable. Check your provider's attribution and service terms when displaying live data.

Rain includes particles and simulated lightning; flashes do not indicate actual lightning detection. Drops have independently randomized positions, fall speeds, lengths, and wind drift. Rain particle counts scale with city area, capped at 800. Snow gradually adds a partial layer to the ground and rooftops while the simulation is active.

Weather particles pause when **City life** is disabled or reduced motion is requested. Optional environment selectors override the supplied props locally; **Automatic** resumes following the supplied weather and lighting values.

<h2 id="lighting">Lighting and simulation</h2>

Automatic lighting follows the browser's local clock independently of the weather API: sunrise from 6–8 a.m., day from 8 a.m.–5 p.m., sunset from 5–7 p.m., and night at other times. Selectors let you combine day, sunrise/sunset, or night with rain, snow, or no precipitation.

[Try the weather example in the playground](./#playground).

<h2 id="monitoring">Monitoring and company data</h2>

The reusable `CityMap` and documentation playground include an optional monitoring panel. It remains visible when the eye button hides the other UI; set `showMonitor={false}` to remove it. The panel shows a local clock and up to four companies currently at high risk, ordered by the start of their current status (`statusChangedAt`). Records without that timestamp are counted separately.

The package receives records through `data`. Replace the array when your application loads new data or receives an update. Company records are not fetched or polled by the map. Your application owns any tables, filters, pagination, and import flows. [Try all of these in the extension example](?page=extending#extension-example).

<h2 id="extensions">Extend the chart with application features</h2>

Compose these capabilities around `CityMap`, as demonstrated in the [extension guide and working example](?page=extending#extension-example). The chart continues to own rendering, camera controls, selection, lighting, and effects; the surrounding application owns data and integration workflows.

| Extension | What you can add | Details and working example |
| --- | --- | --- |
| Combined filters | Filter the full portfolio by name, one or more health states, and an exact category/intersection. | [Filters and pagination](?page=extending#extension-filters) |
| Portfolio counts | Show total and matching companies, health counts, and counts per category/intersection. | [Filters and counts](?page=extending#extension-filters) |
| Paginated cities | Display 100, 250, 500, 1,000, or all companies per city, with transitions between pages. | [City pagination](?page=extending#extension-filters) |
| Comparable building heights | Supply `metricDomain` to preserve the full portfolio's height scale across filters and cities. | [Shared height scale](?page=extending#extension-filters) |
| Synchronized table | List the same companies as the map, reflect selection, and locate a company with focus and zoom. | [Table integration](?page=extending#extension-table) |
| Full-portfolio monitoring | Supply `monitorData` to monitor recent high-risk entries across the portfolio while displaying a subset. | [Monitoring and selection](?page=extending#extension-table) |
| JSON import and sample download | Import and validate files up to 5 MB, download an example, and preserve the current portfolio if validation fails. | [JSON workflows](?page=extending#extension-data) |
| External company data | Load an HTTP(S) JSON source with loading, cancellation, timeout, and error handling. | [Connecting a data source](?page=extending#extension-data) |
| Live rain and snow | Opt in to location-based Open-Meteo weather, with caching, refreshes, and cleanup when paused or disconnected. | [Live weather integration](?page=extending#extension-weather) |

These integrations are available in the extension example. The basic playground continues to use local data and simulated weather. Optional `metricDomain` and `monitorData` props default to the chart's existing behavior when omitted.

[Inspect the implementation source](?page=extending#extension-source).

<h2 id="integration">Integration and distribution</h2>

The package provides plain CSS and Tailwind 4 themes, callbacks, and an imperative camera API. It can render an SSR shell, but WebGL starts only in the browser. In frameworks with Server Components, place the map inside a client boundary.
